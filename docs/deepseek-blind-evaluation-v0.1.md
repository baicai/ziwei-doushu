# DeepSeek 单模型匿名命盘对照评测 v0.1

## 目标

检验“读者觉得自己被说中”的主观体验是否对命盘具有区分度。首版是**个人使用的弱盲对照**，不是真正的研究双盲：读者在提交判断前不知道两份 AI 解读分别来自真实命盘还是合成对照盘，但是可检查浏览器内部数据，模型也可能输出可推测来源的线索。

## 实验步骤

1. 在 `/chart?ai_lab=1&specificity=80` 或 `100` 打开自己已经排好的命盘；出生时辰未知时禁用本实验。
2. 展开“匿名命盘对照 · 实验”，阅读 AI 调用成本和数据提示；只有主动点击才开始。
3. 程序保留用户**已标准化的排盘公历日期、时辰、性别**作为目标盘；构造另一份**合成**出生资料，年份偏移 13 年、月份偏移四个月、时辰偏移五个索引、日期固定为 15 日，同性别。它不是另一人的资料，不宜称为“他人的真实命盘”。
4. 两份调用均传给同一 DeepSeek 接口，`topic=overview`、`style=plain`、相同 specificity 和同一条问题，顺序发送，固定默认模型。若一份调用失败或模型版本不同，则丢弃这轮比较；已经完成的单次模型调用可能仍计费。
5. 使用浏览器随机源等概率决定真实盘显示在 A 或 B。实验进行期间不展示身份和对照标签；用户可选“ A 更像”“B 更像”“两份都像”“两份都不像”“无法判断”，不强迫二选一。
6. 提交后揭晓 A/B 来源。用户可以选择导出只包含匿名编号、A/B AI 文本、模型、明确度、选择结果、真实盘所在位置和生成时间的 JSON。导出不会自动上传服务器，也不直接包含原始出生资料或姓名。
7. 若命盘被重新编辑，旧盲评结果立即清除。关闭实验时可以中止尚未完成的生成，已发出的请求仍可能计费。

## 关键局限

- 模型接收到进行排盘所必需的公历年月日、时辰和性别；使用者需要在点击前知晓。不发送姓名、城市、原始钟表时间或经度。命盘解读可能带出个人线索，应查看导出文件。
- 目前只对照**真实盘与合成对照盘**，不能证明紫微斗数的人格、经历或未来预测具有科学有效性。
- 两次回答的主观风格差异、模型波动可能让用户有其他选择依据。要求模型不透露出生资料，但不能保证它遵守。
- A/B 标签在浏览器组件状态中，不是防篡改的安全盲测；如需正式实验，应由独立服务端保存分配密钥，做到分配隐藏、预注册、交叉复测和多人盲评。
- 只有用户明确点击才进行**两次**额外 DeepSeek 请求。当前只有 WAF IP 级别限流，没有全站费用硬上限；Redis 继续暂缓。
- 如果多人参与，每个参加者应先盲评至少若干个互不重复的真实、对照资料，不要只统计选择自己盘的比例；事先设定最小样本量，进行相关性和基线控制。用户选择 both/neither/unsure 也应计入分母并单独报告。
- 初步本地导出适合收集案例；并非已经完成批量盲评、科学结论或真实 DeepSeek 输出稳定性验收。

## 不做

- 不新增 Qwen、Kimi、其他模型 API Key。
- 不新建 Redis / Database，不存储生辰或云端用户评测库。
- 不引入付费或会员功能。
