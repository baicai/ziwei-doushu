# DeepSeek 深度解读：质量门禁与组合规则 v4

## 已发现的问题（测试记录不含出生资料）
- 即使连续三次输出六主题完整，模型仍可能将“先接手、主导、硬撑”重复到多个章节：六个标题不等于六个独立见解。
- 对同一篇不同输出，可能分别猜测亲近关系中“直接安排”“先忍后说”“先提供解决方案”。没有真实经历时，不能选择其中一个假装命中。
- 日常 AA、借钱、工作先答应后补资源、常熬夜都不应从命盘单独推断成已发生事实。
- 现有自动事实审计是部分结构验证，不等于判断性格或命理是否成立。

## v4 的两层输入
1. `deepChapterEvidence.chapters` 仍是由排盘程序生成的实际宫位、主星、辅星、煞星及四化的事实。
2. `deepChapterEvidence.interpretiveHypotheses` 是按星曜组合触发的解释候选卡，包含话题轴、触发条件、可讨论的行为假设、相反解释和核对问题。它不是生活事实，不能跳过验证。

对于没有命中规则组合的主题，返回弱候选提示，而不是伪造所谓神断。需长期逐步建立有来源、经过审查的组合规则库，不能只靠有限几张卡替代专业知识。

## 运行后质量检查
返回 `deepQualityAudit`：
- `MISSING_TOPICS`：未输出完整六主题。
- `MISSING_REFERENCES`：章节缺少来源编号。
- `SHORT_CHAPTER`：章节文字过短。
- `SIMILAR_CHAPTERS`：三个以上主题含重复的行为主线关键词（启发式）。
- `UNSUPPORTED_PRIVATE_ASSERTION`：明显断言已婚、欠债、经常失眠等（启发式）。

这些是文字编辑层面的告警，不是可信度评分，不代表预测准确或错误。规则无法识别隐含推断、概念重述或非固定模板的幻觉。

## 体验与成本
- 通俗版、深度版继续由用户主动点击，每次各调用一次；不给用户自动重试付费 API。
- 深度版页面展示可展开质量检查，避免将存在告警的内容假装成熟产品。
- 公共 Git 仓库不可包含用户生辰、命盘原始报告或用户历史对话。
- 当前限免；没有支付和权益校验前，不可将此功能称为已经可收费上线。

## 下个验收点
用非真实个人样本和自愿参与者的独立样本，比较 v3 / v4 六章主题重合率、事实引用错误、可证伪行为数、无依据私事推断数，按盲态评估。这次只完成了一个真实盘的 v3 三次输出，不应把结果推广为普遍效果。
