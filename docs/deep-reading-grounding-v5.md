# DeepSeek 深度解读 v5：逐章核对盘面依据

## 本轮实现
- 沿用 v4 的条件规则解释卡、六主题结构及反例设计，不新增模型、不增加自动调用、不接入支付。
- 服务端新增 `buildDeepChapterGrounding`：六主题分别定位本宫、对宫及两组三合；这些事实由当前排盘程序与 `chartEvidence` 目录给出，不让 DeepSeek 编造。
- 每章拆开统计两件事：① AI 引用的编号是否属于本章节主结构；② AI 文字中有多少条被部分事实检查器识别为明确、可核对的主星/空宫事实句。
- DeepSeek v5 写作契约要求每章给出至少一条可直接核查的真实盘面事实，引用本章实际宫位编号；未遵守时仅告警，不用模型输出代替引擎事实。
- 页面在深度版每章单独显示「本章排盘事实 · 非 AI 推断」；此处不算 DeepSeek “预测命中”。模型对生活的推测仍属于待核对的文化解读。
- `deepQualityAudit` 新增三类提示：`WEAK_CHAPTER_GROUNDING`、`UNCHECKED_NATAL_FACTS`、`CONTRADICTORY_NATAL_FACTS`。

## 边界说明
- 检查器是固定句式的部分核验，匹配为 0 不代表实际毫无事实；也不能将引用匹配与“命理解释准确”混为一谈。
- 引用本宫/三方/对宫只表示主题上的关联，不证明引用支持生成的行为推断；引用其他宫位不直接等于错误，标为补充资料。
- 用户真实经历与命盘事实必须分开。不会上传用户私人报告、生辰或个人对话到公开仓库。
- 维持一次点击、一次 DeepSeek 请求；不自动重试、不增加 token 以外的二次推理步骤。

## 验收
1. `npm test` 包括虚构命盘对真实核心宫位引用、误引其他宫位、句式无法验证的回归测试。
2. `npm run typecheck` 与 `npm run build` 仍需由 CI 真实执行。
3. 无 DeepSeek 环境密钥的 CI 不能证明线上正文一定逐章满足 v5；需在部署后使用非私人样本做调用和人工盲评。
