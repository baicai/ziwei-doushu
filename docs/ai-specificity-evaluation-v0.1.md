# 紫微研究 · AI 描述明确度实验规范 v0.1

## 目标

「描述明确度」（specificity）用于控制**传统命盘解读的表达具体性与可核验性**，不是 LLM temperature，不改变出生资料、排盘算法、模型选择或采样温度，不是命中率、统计置信度，也不能证明术数有预测力。

默认值 `0`，请求不传时完全回退到 0，继续原来宽泛的描述层级；本轮在各档位统一增加 **【可以怎么做】** 低风险的情境化行动建议，属于新增功能，不能保证模型逐字重复历史输出。所有模型生成本身可能波动。

## 五档映射

| 输入范围 | 名称 | 输出要求 |
|---|---|---|
| 0–19 | 宽泛（默认） | 保持原有命盘描述粒度，不额外强制特征差异；保留必要证据和温和条件语气 |
| 20–39 | 重点突出 | 按命盘依据选出 1–2 条主要倾向，说明触发条件 |
| 40–59 | 具体行为 | 加入能在日常观察的行动模式和自查问题 |
| 60–79 | 场景与反例 | 3 条更具辨识度的「情境→倾向行为」，同时举不适用情形 |
| 80–100 | 可核验假设 | 3 条可被真实经历否定的假设，列出适用条件、可观察做法、依据、反例与过往 6–12 个月的验证问题 |

这些区间是**人工设计的写作指导强度**，不对应数字上的统计概率。

## 接入方式

- 普通入口：`https://iziwei.vercel.app/chart`，隐藏参数调节，固定 0；无需新用户操作。
- 临时研究入口：`https://iziwei.vercel.app/chart?ai_lab=1`，在 AI 解读位置可见 `0–100` 滑块（每 10 步）。
- 预设样例：`https://iziwei.vercel.app/chart?ai_lab=1&specificity=80`，仅控制当前打开页面的显示设置。
- 两个入口（六专题追问与综合 AI 报告）共享同一设置；调整后需要**再次主动点击 AI 解读**，不会自动触发扣费。
- 最近四次完整报告 AI 结果暂存在浏览器组件状态，便于同命盘对照；不会由本功能自动持久化或上传实验评分。
- 请求参数：`specificity`，整数 0–100；未传、浮点、越界或非法类型时回退 0。
- `ai_lab=1` 是 UI 可见性的实验开关，**不是身份认证或 API 权限控制**；想限制使用须另加鉴权。
- API 采样温度固定沿用 `0.3`，与此参数完全独立。

## 正式有效性验证，不用「说得像」替代「说得对」

1. 准备至少 30 份**获得授权**的匿名出生资料，涵盖性别、月份、时辰及不同星曜组合；不要采集不必要的姓名、联系方式等个人信息。
2. 固定代码提交、历法配置、模型版本、提示词版本和命盘输入；对每份盘至少对照 `0 / 50 / 100` 三档，每档重复 2 次。记录成功率、耗时和 Token 消耗。
3. 对每个输出分别检查：
   - **盘面事实正确性**：引用的星曜、宫位、四化、时间层是否真的存在。任何捏造为严重错误；
   - **辨识度**：是否给出了能区别其他命盘的具体假设，而非放之四海皆准；
   - **可证伪性**：是否有明确的情境、可观察行为、反例/不适用情况；
   - **可操作建议**：是否有可执行的小行动和判断是否有帮助的标准；
   - **一致性**：同一盘重复测试的主要结论是否互相矛盾；
   - **泛化率（反向指标）**：拿同一个解读给多个不同命盘的本人盲评，有多少人都觉得准确。
4. 在不知道对应出生盘的情况下，招募自愿参与者盲读 **本人版本 + 不同盘的对照版本**，先让他们逐句选择「符合 / 不符合 / 不确定 / 无法验证」并举实际例子，最后再看来源。这样才有可能测量是否存在「人人都觉得说中」的效应。
5. 建议记录字段：实验 case 匿名 ID、commit、提示词版本、模型、sampling_temperature、specificity、是否真出生时辰、topic、生成时间、请求成功、费用估算、证据错误数、可证伪句数、建议可执行比例、盲评结果及反例数。**不直接写入敏感出生资料或 AI 问题日志。**
6. 结果报告按分组对比，不因 `specificity=100` 的语气更肯定就给予更高准确性分数。若高档位频繁捏造具体经历或出现自相矛盾，应视为质量下降，必要时降低该档的输出数量。

## 上线质量边界

- 免费 Demo 暂不做订阅、付费、积分等分层。
- 每次 AI 请求仍消耗用户现有 DeepSeek 额度；WAF 只按 IP 限流。
- 跨实例全局预算的 Redis 原子计数已做代码及回归验证，但 **若未配置 `AI_BUDGET_MODE=enforce` 和 Upstash Redis 服务，则尚未启动全局硬上限**。不得以本功能暗示已完成费用保护。
- 模型对不同人的传统命理描述并非经科学验证的人格测验。报告需要用参与者实证反馈而非模型的自我评分来判定。
